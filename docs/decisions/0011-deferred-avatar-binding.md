# ADR-0011：延迟人工绑定与全局头像档案

日期：2026-07-31

## 决定

`opers` 只表示开局编队。召唤物和地图装置可以由 Deploy 动作首次引入，不参与开局编队指纹；编辑器
把可选名称保存在 `frame_replicator.deferred_targets`。开局绑定只处理部署栏当前可见卡片，未出现
目标留到其第一次 Deploy 的目标帧处理。

Runner 在目标帧动作屏障之后只读扫描部署栏：Session 已绑定模板或 `BindingStore.avatars` 全局头像
唯一命中时直接继续；否则显示“新增召唤物绑定”。人工绑定只保存全局头像，不写入编队档案。绑定
期间持续检查尺子，禁止 AFA、触控和逐帧输入；用户切回游戏后还必须取得水位更新、帧号不变的可信
`1x_paused` 样本，才允许部署。

## 原因

召唤物在召唤师部署后才进入部署栏，无法参与开局完整绑定。把它伪装成开局 `opers` 会导致开局
确认永远缺项，并使同一头像在不同编队重复绑定。现有全局头像档案已经提供按名称跨编队保存最新
模板的能力，无需引入 OCR 或完整头像库。

## 后果

- 首次出现需要人工命名一次；同局、重启后及不同编队可复用同名头像档案。
- 历史头像无命中或多卡歧义时必须人工确认，不自动猜测。
- 没有候选卡、取消、运行态、非 1x、离战、帧号变化或焦点返回后缺少新可信样本都会零部署中止。
- 多个同名实体仍共用最新头像；技能和撤退应优先提供 `location` 消除目标歧义。
