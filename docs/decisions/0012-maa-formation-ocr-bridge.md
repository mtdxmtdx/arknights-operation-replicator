# ADR-0012：MAA 战前编队 OCR 与 F0 头像桥接

日期：2026-07-31
状态：已采用，真实画面效果待用户实机验收

## 决定

复刻执行页提供用户主动触发的只读“扫描编队”。程序直接读取用户现有 MAA `resource` 中的姓名
锚点模板、PaddleOCR ONNX 模型、字典、`battle_data.json` 和 `tasks.json`，但不加载
`MaaCore.dll`。识别结果必须经用户逐槽确认，只有作业精确命中会默认选择。

确认结果只形成一次性 Pending。它绑定作业编队指纹、游戏 HWND、窗口尺寸、生成时间，并仅可被
下一次 `RunMode::FromZero` 消费；有效期 30 分钟。重新装载作业、取消、重新扫描、窗口变化、过期
或开始消费都会清除它；非零帧“继续”不读取 Pending。

F0 先恢复 Session、全局头像和编队 profile，再对仍未解释的卡片做桥接。桥接采用 MAA
`BattleAvatarDataForFormation` 的中心裁图和多尺度 NCC 思路，并增加职业兼容、行列互为唯一最佳、
阈值和次优 margin 四重门禁。失败、平局或歧义回退人工绑定；成功项才批量写入现有 profile 与
全局头像档案。召唤物和装置继续使用运行期延迟绑定。

## 理由与后果

- 用户无需训练、安装或维护 OCR；MAA 资源版本是唯一外部内容来源。
- ONNX Runtime 静态链接到程序，发布时无需额外 DLL；仓库仍不分发 MAA 模型和游戏素材。
- 扫描模块的依赖方向只到截图、视觉和作业数据，不能访问 AFA、键鼠或触控接口。
- OCR 和头像相似度都不是自动执行授权；人工确认与保守唯一性门禁避免错误绑定直接落库。
- 真实语言包、分辨率、皮肤和 UI 版本差异只能通过实机验收确认，自动测试不宣称替代。
