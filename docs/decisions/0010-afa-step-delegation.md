# ADR-0010：主复刻逐帧推进委托 AFA

日期：2026-07-30

## 决定

主复刻的每一次 `Pulse` 都委托 AFA `[Hotkeys]/33ms` 动作。该配置项与暂停、恢复、技能、撤退热键
一起成为启动预检必需项；实际键值只从 `Settings.ini` 读取，不能写死为 R。Rust 不再在主路径执行
“恢复键 → 本地毫秒间隔 → 暂停键”，`initial_gap_ms` 仅为旧配置兼容保留。

Runner 仍负责事务边界：逐帧动作前等待 500ms，派发后用尺子确认 running→paused，或在未采到
running 时以连续两条新 paused 样本结算；单条积压 paused 不得结算。到达目标帧后动作前尺子屏障
从 2000ms 缩短为 1000ms，期间仍持续复核目标帧、倍速和暂停状态。

## 原因

用户实机比较确认 AFA 的 `33ms` 过帧比 Rust 本地定时脉冲稳定。继续维护两套运行期时序会让主程序
重复猜测 AFA 已经实现的行为，也会让 `initial_gap_ms` 产生错误的可调预期。

## 后果

- AFA 未配置 `33ms` 时，主程序在会话建立阶段失败关闭，不在运行中回退 Rust 脉冲。
- `afa-step-test` 与主复刻使用同一 AFA 动作；诊断统计可直接用于稳定性判断。
- `PauseController`、`step-test` 和 `step-sweep` 仅保留为历史/诊断工具，不是现役复刻路径。
- 尺子仍是帧数和动作是否安全落地的唯一真源；AFA 热键派发成功不等于 Pulse 已确认。
