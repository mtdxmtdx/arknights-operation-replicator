# 0009：以冻结截止帧建立风险确认式继续会话

- 状态：Accepted
- 日期：2026-07-29

## 背景

实机可能因为手动操作、尺子盲区或一帧误差停在非零帧。原有入口只能从开局接管，旧运行失败后
也不能安全地把状态机线程原地复活。用户需要明确承认已经发生的前缀，再执行作业剩余部分。

## 决定

“开始复刻”只接受可信第 0 帧。“继续”只接受带 `frame_id` 的可信、战斗内、`1x_paused` 非零
样本，并在点击时冻结截止帧。所有目标帧不晚于截止帧的动作整体视为“用户确认完成”；程序不声称
这些动作通过了尺子确认。

确认弹窗必须列出被承认的动作、按作业推导的场上状态、下一动作、头像档案问题和风险。确认前
不产生输入。确认时重新检查 AFA、尺子和头像档案；启动过程最终只能在
`cutoff <= elapsed <= next_action.frame` 的样本上接管，超过下一动作立即失败，截止帧不随画面推进。

继续创建新的 `Session`、`Runner` 和 `Machine`。Session 按动作前缀回放 Deploy/Retreat 播种场上
位置。绑定只要求后续还要部署、且当前推导为不在场的干员；当前在场但后续会再次部署的干员必须
从跨编队头像档案恢复，缺档案时阻止继续，不引入运行期延迟绑定。

继续运行成功时结果为“带风险完成”，并报告多少动作为用户确认完成。该结果不能计入 M9 精确
复刻验收；已经由尺子确认的旧行状态仍保留为普通动作确认。

## 后果

- F1 可以作为冲过第 0 帧但尚未跳过动作的显式风险入口。
- test1 在 F11 继续会推导桃金娘位于 `(3,2)`，跳过 F10 部署并从 F40 技能开始。
- 同帧动作不能只跳过一部分；截止帧是包含边界。
- 到达或超过最后动作后没有剩余工作，“继续”不可用。
- 旧 `bindings.json` 仍可加载；新版本在人工或档案绑定时逐步补齐全局干员头像库。
