# 部署后 Resume 前必须经过稳定暂停窗口

## 状态

已接受（2026-08-03）

## 决定

非最终 `Deploy` 完成既有动作确认后，Runner 继续读取尺子并保持 500ms 的稳定窗口。窗口内每条
样本仍须满足该动作目标帧的可信 `1x_paused`；running、错帧、非 1x 或离战立即中止。窗口通过后
才标记动作完成，并允许同帧下一动作或发送一次 AFA `ReleasePause`。

`ReleasePause` 仍遵守 ADR-0005：每个运行区间只派发一次并等待 running 回执，不因超时盲目重发。
若回执超时，状态机报告“恢复运行未生效”，不再误报为“没有新分析帧”。

## 原因

HS-9 实机日志在 F752、F991、F1586 三次记录到相同模式：部署动作已由新目标帧暂停样本确认，随后
发送 `ReleasePause`，但接下来的 119–121 条可信样本始终为 `1x_paused`，两秒后中止。三次均发生
在带朝向的部署之后；重新接管并等待后，同一帧的 Resume 均正常确认。说明原有 150ms 手势尾延迟
不足以稳定覆盖部署 UI/输入收尾，而尺子采集与动作确认本身正常。

## 后果

- 每个非最终部署增加约 500ms 墙钟时间，但不推进逻辑帧。
- 稳定窗口持续消费权威尺子样本，不使用会掩盖错帧的盲目睡眠。
- 最终部署仍按零输入 Finish 直接收尾，不增加无意义的 Resume 前等待。
- 自动测试覆盖稳定窗口时长、意外 running 拒绝和 Resume 专用超时原因；真实 AFA 热键效果仍需
  实机验收。
