## 2. 前置条件

- AFA、ArknightsCostBarRuler、游戏和复刻器都由用户以管理员权限启动。
- 尺子已校准，费用条可读，鼠标不遮挡费用条。
- AFA 实际配置由复刻器只读记录；本验收 profile 预期为：

```ini
[Hotkeys]
PressPause=g
ReleasePause=Space
PauseSkill=XButton2
PauseRetreat=XButton1
33ms=r

[Main]
AutoBeginPause=1
DefaultStrongHoldProtocol=0
```

- `examples/sample-job.json` 的 `10/40/60` 可直接用于精确链路验收；首动作没有第 60 帧下限。
- 作业至少覆盖 Deploy、Skill、Retreat；最后一次动作后应停在该动作的目标帧 `1x_paused`。

任一配置不同、AFA 状态灯非绿色、尺子读数不可信或游戏不在目标关卡时，停止本轮；复刻器不会
修改 AFA 配置，也不会回退旧 Rust 技能/撤退时序。

## 3. M8：启动接管

### 3.1 开始按钮门禁

1. 装载作业，但还没有进入关卡时，确认“开始复刻”不可用。
2. 进入目标关卡，等待 AFA 自动暂停。
3. 确认尺子为带 `frame_id` 的可信战斗内 `1x_paused` 第 0 帧；此时“开始复刻”才可用。
4. 点击“开始复刻”，不要按开局暂停键；随后手动点击游戏窗口。

通过判据：

- 日志出现 `startup phase: 等待游戏回到前台` 和 `检测到游戏窗口已回到前台`。
- 焦点后出现新的 `接管样本通过`，其 `frame_id` 高于日志中的水位。
- 接管前没有 `dispatching AFA runtime pause`，也没有复刻器补发的开局 `PressPause`。
- 15 秒内不把游戏切回前台时安全中止，期间没有游戏输入。

### 3.2 已有完整绑定档案

使用已经保存过完整绑定档案的编队：

1. 按 3.1 启动并切回游戏。
2. 确认没有弹出人工绑定面板，日志显示完整档案已恢复。
3. 编队准备后保持或重新切回游戏，等待最终接管样本。

通过判据：最终依次出现 `等待最终焦点交接`、`验证接管样本` 和新的 `接管样本通过`，随后才进入
巡航或逐帧推进。

### 3.3 暂停首样本的人工绑定

使用未命中现有绑定档案的编队签名；不要删除现有 `bindings.json`：

1. AFA 停在 `1x_paused` 后点击开始并手动切回游戏。
2. 首个焦点后样本仍为 paused 时，复刻器窗口最多尝试激活一次并显示绑定面板。
3. 完成绑定并确认后，手动把游戏重新切回前台。
4. 等待最终焦点后的新接管样本，再观察 Machine 开始推进。

通过判据：绑定期间没有 AFA 暂停/恢复输入；最终接管发生在用户重新切回游戏之后。

### 3.4 running 首样本且无档案（负向用例）

只在可安全退出重开的关卡执行。使用未命中档案的编队，并让焦点后的第一条可信样本成为
`1x_running`。

通过判据：本轮立即中止并提示“running 但没有完整绑定档案”；不显示人工绑定面板、不发送 AFA
暂停键，也不继续派发 Deploy/Skill/Retreat。

## 4. M8：运行期动作链

完成一次 Deploy → Skill → Retreat：

1. 每个巡航区间只允许一条 `dispatching AFA runtime resume`。
2. Resume 后可以出现多条 `runtime resume waiting for running state`，但必须由一条
   `runtime resume confirmed` 收尾，确认前不得再次 Resume。
3. 接近目标时只允许一条 `dispatching AFA runtime pause`；收到 `runtime pause confirmed` 后才可 Pulse。
4. Pulse 必须以 `running_then_paused` 或 `two_paused_samples` 结算；单条旧 paused 不能结算。
5. 每个动作派发后必须出现目标帧的 `动作确认通过`；任何运行态确认样本都应立即中止。
6. 最后动作确认后不再发送输入，UI 显示跨帧数为 0，游戏和尺子都停在最后目标帧的 `1x_paused`。

## 5. 风险确认式继续（不计入 M9）

使用 `examples/test1.json` 单独验收；这些运行只证明继续功能行为，不属于精确复刻样本。

### 5.1 F11 接续主路径

1. 正常进入关卡并让 F10 桃金娘部署实际完成，在可信 `1x_paused` F11 停住。
2. 确认“开始复刻”不可用、“继续”可用；点击“继续”后先不要确认。
3. 核对弹窗：截止帧 F11；跳过列表只有 F10 桃金娘部署；场上推导为桃金娘 `(3,2)`；下一动作
   是 F40 桃金娘技能；同时显示风险说明。
4. 点击“承担风险并继续”，按提示完成焦点交接和仅剩的必要绑定。
5. 确认时间轴 F10 行显示绿色“用户确认”，F40 技能及 F150 以后动作按原作业执行。
6. 运行完成后摘要必须是“带风险完成，1 个动作为用户确认完成”，不得显示为普通精确完成。

### 5.2 冲过一帧

在首动作之前的可信 `1x_paused` F1 点击继续。弹窗应显示没有被跳过的动作、下一动作仍为 F10；
确认后从 F10 开始执行。完成摘要中的用户确认动作数必须为 0，但仍属于带风险完成、不能计入 M9。

### 5.3 冻结边界负向用例

打开 F11 确认弹窗后，不确认，先让画面推进到 F41 或更晚，再点击确认。必须拒绝继续并显示允许
区间 F11..=F40；不能把 F40 技能自动加入跳过列表，且不得发送输入。

在 F249（最后动作帧）或之后停住时，“继续”必须不可用。若某个在场干员后续还会撤退并重新
部署，而 `bindings.json` 没有其头像档案，弹窗必须列出缺档案并禁用确认。

### 6.1 AFA 过帧诊断（与主链路同一动作）

`afa-step-test` 通过 AFA 当前 `[Hotkeys]/33ms` 热键执行 1 倍速过帧，尺子独立等待稳定
`running → paused` 并统计真实推进量。工具默认和最多执行 500 次；它不修改 AFA 配置。主复刻已
委托同一个 `33ms` 动作，诊断结果可直接反映现役逐帧路径。

准备条件与普通单帧验收相同，另外要求鼠标留在游戏客户区内但不能遮挡费用条。以管理员 PowerShell
运行：

```powershell
Set-Location -LiteralPath 'D:\Arknights Operation Replicator\replicator'
.\target\release\afa-step-test.exe 500
```

通过判据：完成 `500/500`、跨帧为 0、负数推进为 0、`+1` 命中不少于 125 次。连续 10 次空脉冲
会提前停止，并提示检查鼠标是否位于客户区。

## 7. 失败即停与回传材料

出现以下任一情况立即停止当前轮，不盲重试热键：

- 尺子绝对帧越过目标，或 UI 与尺子显示不一致；
- 同一巡航区间出现第二条 Resume；
- Pause 未确认就开始 Pulse；
- 单次 Pulse 推进多帧；
- 动作确认收到 running、非目标帧、2x、离战或超时；
- AFA 退出、降权、配置指纹变化，或游戏失去前台。

每轮回传：

1. 与本页一致的二进制 SHA-256；
2. 完整 `replicator.log`；
3. AFA 七项实际配置值；
4. 最终尺子与游戏画面截图；
5. M9 轮次对应的录像和 CSV。

旧日志、旧父目录二进制、只有“已派发”而没有画面/尺子确认的记录，都不能作为当前版本通过证据。
