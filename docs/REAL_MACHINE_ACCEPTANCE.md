## 2. 前置条件

- AFA、ArknightsCostBarRuler、游戏和复刻器都由用户以管理员权限启动。
- 尺子已校准，费用条可读，鼠标不遮挡费用条。
- AFA 实际配置由复刻器只读记录；本验收 profile 预期为：

```ini
[Hotkeys]
PressPause=g
ReleasePause=Space
PauseSkill=XButton2
PauseRetreat=XButton1
33ms=r

[Main]
AutoBeginPause=1
DefaultStrongHoldProtocol=0
```

- `examples/sample-job.json` 的 `10/40/60` 可直接用于精确链路验收；首动作没有第 60 帧下限。

修改 AFA 配置，也不会回退旧 Rust 技能/撤退时序。

## 3. M8：启动接管

### 3.1 开始按钮门禁

1. 装载作业，但还没有进入关卡时，确认“开始复刻”不可用。
2. 进入目标关卡，等待 AFA 自动暂停。
3. 确认尺子为带 `frame_id` 的可信战斗内 `1x_paused` 第 0 帧；此时“开始复刻”才可用。
4. 点击“开始复刻”，不要按开局暂停键；随后手动点击游戏窗口。

通过判据：

- 日志出现 `startup phase: 等待游戏回到前台` 和 `检测到游戏窗口已回到前台`。
- 焦点后出现新的 `接管样本通过`，其 `frame_id` 高于日志中的水位。
- 接管前没有 `dispatching AFA runtime pause`，也没有复刻器补发的开局 `PressPause`。
- 15 秒内不把游戏切回前台时安全中止，期间没有游戏输入。

### 3.2 已有完整绑定档案

使用已经保存过完整绑定档案的编队：

1. 按 3.1 启动并切回游戏。
2. 确认没有弹出人工绑定面板，日志显示完整档案已恢复。
3. 编队准备后保持或重新切回游戏，等待最终接管样本。

通过判据：最终依次出现 `等待最终焦点交接`、`验证接管样本` 和新的 `接管样本通过`，随后才进入
巡航或逐帧推进。

### 3.3 暂停首样本的人工绑定

使用未命中现有绑定档案的编队签名；不要删除现有 `bindings.json`：

1. AFA 停在 `1x_paused` 后点击开始并手动切回游戏。
2. 首个焦点后样本仍为 paused 时，复刻器窗口最多尝试激活一次并显示绑定面板。
3. 每张未识别可见卡使用下拉菜单选择作业 `opers` 中对应名称；不要手工输入名称。
4. 点击“完成当前可见绑定”后，按钮先显示“正在保存”，面板只有在日志确认保存成功后才关闭。
5. 状态栏提示“绑定已保存”后，手动把游戏重新切回前台。
6. 另用同时包含先锋与至少一种其他职业的未保存编队重复一次；所有部署栏卡片都必须出现。职业模板
   未命中的卡片允许显示“未知”，但不能消失，并且必须可以绑定。
7. 等待最终焦点后的新接管样本，再观察 Machine 开始推进。

关闭并重新打开程序、装载同一作业与编队再运行一次：如果当前可见卡都已由档案识别，即使作业里
仍有稍后才出现的召唤物/装置名称，也不得再次弹出开局绑定面板。

通过判据：绑定期间没有 AFA 暂停/恢复输入；最终接管发生在用户重新切回游戏之后。

### 3.4 running 首样本且无档案（负向用例）

只在可安全退出重开的关卡执行。使用未命中档案的编队，并让焦点后的第一条可信样本成为
`1x_running`。

通过判据：本轮立即中止并提示“running 但没有完整绑定档案”；不显示人工绑定面板、不发送 AFA
暂停键，也不继续派发 Deploy/Skill/Retreat。

## 4. M8：运行期动作链

完成一次 Deploy → Skill → Retreat：

1. 每个巡航区间只允许一条 `dispatching AFA runtime resume`。
2. Resume 后可以出现多条 `runtime resume waiting for running state`，但必须由一条
   `runtime resume confirmed` 收尾，确认前不得再次 Resume。
3. 接近目标时只允许一条 `dispatching AFA runtime pause`；收到 `runtime pause confirmed` 后才可 Pulse。
4. Pulse 必须以 `running_then_paused` 或 `two_paused_samples` 结算；单条旧 paused 不能结算。
5. 每个动作派发后必须出现目标帧的 `动作确认通过`；任何运行态确认样本都应立即中止。
6. 非最终 Deploy 的动作确认后必须出现同帧的 `部署后稳定确认通过`，其后才可派发 Resume 或同帧
   下一动作；不应再出现动作完成后始终 paused、两秒后误报“没有新分析帧”的停止。
7. Resume 真正未生效时应提示“恢复运行热键已发送，但游戏仍保持暂停”，且不得盲目重发。
8. 最后动作确认后不再发送输入，UI 显示跨帧数为 0，游戏和尺子都停在最后目标帧的 `1x_paused`。

### 5.1 F11 接续主路径

1. 正常进入关卡并让 F10 桃金娘部署实际完成，在可信 `1x_paused` F11 停住。

### 5.2 冲过一帧

### 5.3 冻结边界负向用例

## 8. 战前编队 OCR 与 F0 头像桥接

cargo run --release -p repl-app --bin formation-scan -- .\examples\test1.json

   一个槽位、忽略一个槽位、取消后重扫，确认选择不会越槽串值。

   对应头像和 profile，单纯扫描/取消/确认但未开始不得写档案。

## 10. 失败即停与回传材料

出现以下任一情况立即停止当前轮，不盲重试热键：

- 尺子绝对帧越过目标，或 UI 与尺子显示不一致；
- 同一巡航区间出现第二条 Resume；
- Pause 未确认就开始 Pulse；
- 单次 Pulse 推进多帧；
- 动作确认收到 running、非目标帧、2x、离战或超时；
- AFA 退出、降权、配置指纹变化，或游戏失去前台。

每轮回传：

1. 与本页一致的二进制 SHA-256；
2. 完整 `replicator.log`；
3. AFA 七项实际配置值；
4. 最终尺子与游戏画面截图；
5. M9 轮次对应的录像和 CSV。

旧日志、旧父目录二进制、只有“已派发”而没有画面/尺子确认的记录，都不能作为当前版本通过证据。
