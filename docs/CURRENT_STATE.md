# 当前状态

更新时间：2026-07-27（Asia/Shanghai）

## 当前目标

完成逐帧推进偶发漏暂停导致的约 30 帧超跑修复，并准备实机复验。

## 已验证成果

- 运行期发送暂停键后进入 `ConfirmingPause`，不再把按键发送成功当作暂停成功。
- 尺子确认 `paused=true` 后才允许脉冲；确认窗口期间帧数持续增长会触发有限重试，避免盲等 1000ms。
- 每次脉冲前的 1000ms 稳定等待会消费新尺子样本；检测到暂停丢失会取消脉冲并重新请求暂停。
- 脉冲成功发送后才开始记录 `pulse_in_flight`，避免取消的脉冲被整定器误计数。
- `cargo test --workspace` 和 `cargo build --release` 均通过。

## 关键决定

- 保留 1000ms 慢速稳定窗口，但把盲等待改为可观测等待。
- 开场暂停继续使用较宽的确认窗口；接近动作目标帧时运行期暂停使用较短窗口并最多重试 2 次，以保留 `FRAME_LEAD` 安全余量。
- 持续无法确认暂停或已经越过目标时安全中止，不发送可能进一步超跑的脉冲。

## 当前风险与下一步

- 尚未完成 Windows 实机复验；需用最新 release 可执行文件跑 `examples/sample-job.json`，记录目标 10/60/180 的实际帧与暂停重试情况。
- 若实机仍出现暂停确认延迟超过当前窗口，应依据日志调整 `RUNTIME_PAUSE_PROBE_LIMIT`，不可恢复盲等逻辑。
